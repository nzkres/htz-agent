## 选择顺序

| 路线 | 现在的下一步 | 主要门槛 | 达不到时 |
|---|---|---|---|
| 1. N100/N150 核显迷你机 | 找到可免费试用的完整配置整机 | 核显能否实际运行游戏并同时截图/OCR | 停止追加内存或外接显卡等投入，转路线 2/3 |
| 2. M920x Tiny 原装 RX560 4GB 版 | 核对具体实物配置，取得含附件的整机报价 | 实际独显、二手状态、专用附件及游戏表现 | 不接受用同名核显机替代；换候选或转路线 3 |

若能免费借到任一路线的合适设备，优先用它完成最小验证。若以后准备付费，可先比较路线 2 的完整整机与路线 3 的全套总价；路线 1 只有实机表现通过后才进入购买候选。这个顺序是控制试错成本的建议，不是价格或兼容性结论。

官网当前最低要求列出 i3、8GB 内存、GTX 750 及以上显卡；推荐 i5、16GB、GTX 1060 及以上、SSD。N100/N150 核显不能据此宣称达标；RX560 等候选也要以实际客户端测试为准。[游戏官方下载及配置要求](https://htz.duoyi.com/down/)

## 路线 1：N100/N150 + 16GB + SSD

1. **确认完整型号。** 区分整机、准系统和主板，列出是否包含内存、SSD、电源、散热、无线网卡、显示线和系统授权。内存和 SSD 接口以具体主板规格为准。
2. **取得全套报价并安排免费试机。** 固定单开、低画质和一个适合识别的窗口尺寸。先使用已有显示器和外设；没有免费试机条件时，保持“性能未验证”，不先买来赌兼容性。
3. **验证实际游戏表现。** 在获准使用的实体 Windows 中安装官方客户端和驱动；用户直接输入凭据，进入角色。试运行城镇、对话、背包和一场普通战斗，再同时采集窗口截图、运行本地 OCR，观察卡顿、错误、截图新鲜度和识别耗时。建议约 30 分钟作为初步排查，不作为长期稳定性证明。
4. **做继续或停止判断。** 若客户端拒绝运行、频繁掉线、画面更新不足或 OCR 运行后明显拖慢游戏，记录原因并停止该候选。若通过，再进入下文共同的软件开发及一次修业验证。
5. **未来采购时复测交付实物。** 试机配置与到货配置要一致，核对退换条件和所有附件；重新跑相同测试，不把另一台同型号的结果直接算作到货通过。

若想自己组装 N100 小主机，可把 ASRock N100DC-ITX 当作接口核对示例：它使用板载 N100、桌面 DDR4 DIMM 和外置 19V 电源，电源适配器不随主板附送。它与使用笔记本 SO-DIMM 的迷你整机不能共用一份配件清单。先比较完整总价，再决定整机或组装。[主板官方规格](https://www.asrock.com/mb/Intel/N100DC-ITX/)

## 路线 2：M920x Tiny + 原装 RX560 4GB + 16GB + M.2 SSD

1. **核对实际实物，而不只看标题。** 取得 CPU 完整型号、内存容量、SSD 型号/健康信息，以及设备管理器中的 RX560 4GB 信息。M920x 存在核显配置，“M920x”字样不能证明带独显。
2. **核对整机附件和维护状态。** 确认配套显卡、转接部件、散热完整，电源型号/额定输出匹配，显示线或转换头可用；检查 BIOS 是否受密码锁定、风扇噪声和接口。官方规格列出 135W 适配器和 Mini DisplayPort 独显输出，这些需要计入完整报价，不能只报裸机价。
3. **核对存储空间。** 优先按 M.2 SSD 安排系统和游戏；确认所选实物中独显与 2.5 英寸硬盘位的占用关系。内存、SSD 容量与是否有合法可用的 Windows 授权逐项确认，不把“装好了系统”当成授权依据。
4. **借机或现场试机。** 用实际交付配置完成与路线 1 相同的游戏及截图/OCR 检查。用户在受控客户端输入账号，账号密码不交给卖家，不放进代码或聊天。记录配置、温度/噪声异常、掉线和截图结果。
5. **通过后进入共同软件验证。** 若未来预算允许购买，再核对总价、退换约定和配件清单，到手重复试机；当前不下单。

RX560 是该机型的官方可选配置，但不能据此假设任意桌面显卡都能装进 1L 机箱；也不能保证每台二手机已带齐对应部件。[联想 M920x Tiny 官方规格](https://psref.lenovo.com/syspool/Sys/PDF/ThinkCentre/ThinkCentre_M920x_Tiny/ThinkCentre_M920x_Tiny_Spec.html)

## 路线 3：小机箱 + i5-8500 类平台 + 16GB + SSD + 独显

1. **先确定体积和是否用标准配件。** 先选机箱允许的主板、电源、CPU 散热器及显卡尺寸，再选具体型号。若使用品牌小机箱，查清专用主板、电源接口和扩展槽功率限制。
2. **列完整配件清单。** 至少包括 CPU、主板、内存、SSD、独显、电源、散热器、机箱、必要风扇、网卡/网线、显示线及系统授权情况。i5-8500 仅为平台示例，必须用主板官方 CPU 支持表核对具体处理器和所需 BIOS。
3. **逐项核对兼容和总价。** 检查显卡长度/高度/厚度、全高或半高挡板、槽位、供电接口、电源持续输出和散热空间。显卡以游戏官方要求为筛选起点，具体型号待整套报价后确定；不默认任何小机箱都能装下某张显卡。把全部费用与路线 2 的完整整机报价比较。
4. **先借现成相近配置做验证。** 有免费且获准使用的设备时，先跑客户端、窗口采集和 OCR。没有时可以完成清单与兼容性核查，但不能报告游戏通过。未来预算获准后，才采购并装机。
5. **装好后分层测试。** 先确认 BIOS 识别 CPU/内存/SSD、驱动和散热正常，再跑真实游戏及截图/OCR；通过后进入共同软件验证。出现硬件错误先解决硬件，不通过脚本超时或反复点击掩盖问题。

## 三条路线共用的软件与验收步骤

这些是仍需实施的任务，换一台电脑不会自动补齐代码。关联现有 [TASKS.csv](../TASKS.csv) 和 [最小实现清单](MINIMUM_PLAN.md)。

| 顺序 | 工作 | 通过条件 |
|---|---|---|
| A / T01 | 确定获准的实体 Windows、官方驱动和客户端；用户人工登录选角 | 客户端接受环境，角色/区服可核对；保留使用期限及费用记录 |
| B / T02、T03、T04 | 接入实时窗口采集、坐标换算、前台检查、识别校准、单次入口和停止开关 | 截图确为当前目标窗口，识别结果与按钮一致；失焦/未知状态停止 |
| C / T07～T10 | 只实现一条物资修业：读取任务和完成次数 N，核对已有物品及数量，跟踪到指定 NPC，交付一次 | 实际交付正确物品/数量，出现明确完成确认，游戏次数变为 N+1；缺物或分支不支持就停止 |
| D / T11，V0 | 真机运行一次，用户人工登录和选角单独记录 | 留存脱敏的任务前后证据，未重复提交；人工登录不算自动登录能力 |
| E / T05、T06、T12，V1 | 用户在客户端输入凭据后，脚本继续选区、选人物、核对身份、进入游戏并完成一次修业 | 整段真实流程通过；密码/验证码不进入脚本、聊天、日志或发布截图 |
| F / 后续阶段 | 验证远程查看断开、重新连接、重启后的状态；再有限重复并扩展六项日常 | 每个条件分别实测；无显示器运行时另验截图和输入，不把一次成功当成无人值守已完成 |

第一轮要求背包已有足够且适用的物资，任务次数 N 可读；若当天次数已满或当前任务不支持，则停止。第一轮不自动买物品，不充值，不扩展战斗和通用寻路。先完成 V0，再做 V1 和循环。

普通规则、模板匹配和 OCR 在本机运行，不启用新增计费模型 API。真实截图、角色资料、运行日志和本机配置不提交 GitHub。远程工具和显示器状态可能改变窗口、分辨率、焦点及截图内容，需要在实际使用方式下重新校准。
