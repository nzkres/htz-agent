## 1. 仓库实际具备什么

上游有 Windows 截图、Win32 鼠标键盘输入、EasyOCR、YOLO 接口、MiniMax 决策调用、师门任务类、地图数据与导航类。实际连接在 `ShiMenTask` 中的是截图、视觉、决策、执行器；OCR、Navigator 和 GameState 并没有接入这条任务主流程。

仓库没有根目录 `main.py`、`README.md` 或实际 `config.yaml`，仅有 `config.yaml.example`；没有登录、区服、选人物流程，也没有独立的当前电脑版修业实现。`tasks/shimen.py` 底部有 `__main__`，因此不能说“完全没有入口”，但没有完整可用的启动流程。`pyproject.toml` 没有 CLI 命令声明。

`assets` 只有三张地图名称 PNG：青河镇、长安城、大唐国境。没有 `assets/weights/htz.pt`、登录/角色/修业按钮模板、标注数据或真实游戏闭环验收记录。源码内的示例、TODO 和固定值不能当作这些功能已经完成。

### 坐标约定必须一起改

当前截图使用整窗 `GetWindowRect`；点击也加同一个整窗左上角。二者原点在现有实现中一致，不能简单判定“所有点击必然错位”。真正的问题是函数名/注释称为 client 坐标、独立窗口绑定、手机式比例点位以及没有 DPI/尺寸校验。

最小版可暂时保持整窗坐标并固定尺寸；若采用客户端区域，应同时使用 `GetClientRect + ClientToScreen` 更新截图和点击，不能只改一边。MSS 读到的是桌面区域，输入发往当前桌面，必须在每次操作前确认目标窗口仍是前台且未被遮挡。

## 4. 其他缺口与可延后项

- 登录：缺客户端启动/更新等待、登录页识别、人工输入等待、异常与断线识别。
- 选人物：缺区服和角色唯一匹配、已选中状态、进入按钮及入场后的身份确认。不能默认第一个角色就是目标。
- 修业：缺任务追踪读取、物品名/数量解析、背包查找、数量校验、返回/交付、完成次数读取与重复提交保护。
- 模板：三个地图名称模板不覆盖上述界面。需从获准的真实客户端采集并按客户端尺寸/DPI/主题标注；游戏版本或布局变化使校准失效。
- 证据：缺状态转换记录、动作后新截图、失败原因和真实完成回执。账号登录阶段不截图，或仅保存已遮蔽的非敏感区域。
- `ocr.py:17` 模板目录依赖工作目录；`:34,45` 重复 `_ensure_init`。改为配置/仓库基准路径，再清理重复定义。
- `executor.py:105–107` 很短拖拽可能除零；`:187–190` 又把屏幕绝对坐标传给加窗口偏移的拖拽。第一版禁用拖拽相关组合动作。
- `vision.py:189–225` 保底按钮短名与检测类别 `*_btn` 命名不统一；`:348–353` 血量为占位值。第一版不接战斗决策。
- `game_state.py:9–18` 门派包含测试/示例内容，不是当前目标角色的可靠数据；不能据此判断人物身份。
- Android 仅有截图等 ADB 操作，执行器是 Windows Win32；不能据此宣称支持官方安卓助手的完整自动化。
- 上游 anti_ban 配置和随机延迟不能证明规避检测、运行环境被接受或账号安全，本次不采纳这些结论，也不实现环境伪装。
- `config.yaml.example` 只在注释中提到 `MINIMAX_API_KEY`，没有设置 `api.api_key: ${MINIMAX_API_KEY}`；决策器只读配置键，因此单独设置环境变量也不足以完成该路径的初始化。初版不需要此依赖。
- 上游 `.gitignore` 把部分 `*.pt`、`*.png` 规则和解释放在同一行，不能可靠匹配期望文件。本次仅修正忽略规则并增加本机配置/运行证据目录，且移除对 `test_*.py` 的全局忽略，方便后续提交真正的验证代码；上游已跟踪的三张地图模板仍保留。

## 5. 推荐复用路径

第一版只取“窗口截图 + 单次输入 + 配置 + 模板/受限 OCR”的基础，另写可逐步检查的状态机。不要修完整战斗 AI、训练 YOLO 或扩充通用地图数据库后才开始验收。

登录、选人物和物资修业需要新增的状态与证据，见 [最小实现清单](MINIMUM_PLAN.md)。所有实现任务当前均待执行；静态分析不会把任何游戏步骤标记为完成。
