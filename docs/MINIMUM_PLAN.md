# 登录、选人物和一次修业：最小实现清单

## 1. 这次最小验证的定义

目标是：在客户端接受的 Windows 环境中，用户在官方客户端输入凭据，程序识别登录成功、选中配置中的唯一角色、进入游戏，再完成一次当前实际可做的“收集物资并交付”修业，留下可复核的游戏内证据。

这是**人工输入凭据的登录流程 + 自动选角/入场/一次受支持任务**；不把它描述成无人值守密码登录。短信、验证码或异常验证继续由用户在客户端处理，等待期间不发输入。区服/角色资料保存在仅本机配置，仓库只提交占位示例。

单窗口、单角色、固定窗口尺寸/DPI；成功一次即停止。第一次可在已持有所需物品时验证交付闭环。缺物或出现非物资分支会明确停止，不能因此登记成功；自动采购、战斗、捕捉、六项完整日常和长期掉线恢复后续再做。

## 2. 开工前必须满足

- [ ] E0：执行环境能通过客户端的正常登录和运行检查。此前 Windows 虚拟机被客户端拒绝且已删除；本仓库不能解决该限制。租用服务的名称或“有 GPU”本身不代表游戏接受，先由真实客户端验证。
- [ ] E1：安装官方客户端并完成更新；可见桌面会话保持可用，锁屏/断开远程连接后是否还能捕获画面和输入需单独实测。
- [ ] E2：目标区服和角色由用户确认，能接修业；本轮任务、物品与数量必须从当前画面重读，不能沿用历史示例“驱魔丹”。
- [ ] E3：有能完成一次受支持任务的物资或补充物资的人工准备；不预先假定背包足量，也不自动购买。
- [ ] E4：采集当前版本的登录状态、角色选择、入场、任务面板、背包/交付和完成标志；校准明确的窗口尺寸/DPI及区域。

环境尚未满足时可做只读识别与离线解析，不能写“真实流程已通过”。

## 3. 最少需要哪些运行文件（计划，当前不存在）

| 计划文件 | 职责 |
|---|---|
| `minimal/run.py` | 单一入口、状态机、有限等待/重试、停止与结果输出；不继承上游 BaseTask 的 AI 初始化 |
| `minimal/desktop.py` | 共享 HWND、截图、受控点击/按键；从上游截图和输入代码整理所需最小部分 |
| `minimal/recognition.py` | ROI 模板和受限 OCR、身份/任务字段读取、唯一候选、返回未知状态 |
| `minimal/config.example.json` | 客户端路径、区服/角色占位、窗口约束、超时、已校准资源版本；不含密码 |
| `minimal/requirements.txt` | 最小图像、Win32 和所选 OCR 依赖；不装不使用的 YOLO/API SDK |
| `assets/minimal/` | 必要的脱敏 UI 小模板与校准元数据；不得提交含账号/聊天内容的整屏截图 |

本地 `config.local.json`、`runs/<run-id>/actions.jsonl`、`result.json` 和脱敏证据只在执行机保存并被 Git 忽略。上游 `core/__init__.py` 急切导入视觉/决策，因此初版应避免直接导入整个 core 包，或先改为延迟导入。不要为了少写代码而隐式恢复全部无关依赖。

依赖可从 Python 标准库、MSS、Pillow、OpenCV/numpy、pywin32 起步。若模板无法读取动态任务名/物品数量，再使用已有 EasyOCR 基础；它会增加模型/运行时依赖，应配置 CPU 和本机缓存，不需 MiniMax key。

不预设硬性行数目标；功能和状态判断缺失不能靠减少代码掩盖。先实现六个小入口：`check-config`、`inspect`、`login`、`select-role`、`enter-game`、`xiuye-once`；另设 `all` 只串联已验证步骤。以上是拟定接口，本次尚不可运行。

## 4. 状态转换和动作门槛

| 当前状态 | 识别条件 | 允许动作 | 成功后的新证据 |
|---|---|---|---|
| PREFLIGHT | 唯一有效窗口、正确尺寸/DPI、已校准资源 | 只检查；必要时启动配置中的官方客户端 | 可识别登录/角色/游戏界面之一 |
| LOGIN_WAIT_USER | 官方登录区域存在 | 暂停输入，用户亲自填写凭据并完成验证 | 出现区服/角色页；没有连接或环境错误 |
| SERVER_SELECT | 配置区服唯一匹配 | 点击已识别的目标区服；若当前页已是选角色可跳过 | 目标区服身份已确认 |
| CHARACTER_SELECT | 指定角色唯一匹配 | 点击该角色 | 选中态、角色名/可用 ID 与目标一致 |
| CHARACTER_SELECTED | 目标角色已选、进入按钮唯一 | 点击进入 | ENTERING 后出现稳定游戏界面 |
| IN_GAME | 地图/人物状态和角色身份共同确认 | 打开实际任务面板；已在游戏则从这里继续 | 当前任务状态和基线完成数 N |
| READ_QUEST | 能读取任务名、本轮/目标、要求物品/数量 | 已有修业则接续；无任务时仅选择明确“修业”选项接取一次 | 接取后新的任务文本和任务标识 |
| CHECK_BAG | 任务是已支持物资分支 | 查背包物品名与数量，核实足量 | 同一任务及具体可交付物品 |
| READY_TO_SUBMIT | 同一任务、NPC 身份、物品、数量再次一致 | 使用已校准任务追踪/返回按钮；到达后识别交付界面 | 指定任务的交付选项与所交物品 |
| SUBMIT | 唯一明确交付按钮且无货币/采购歧义 | 提交一次，进入等待状态 | 提交后的新画面，不能重复点击提交 |
| VERIFY_COMPLETION | 有明确任务完成反馈 | 仅观察任务计数与追踪变化 | 游戏内计数由 N 到 N+1，并且与本任务完成反馈一致 |
| DONE | 完成证据已成立且尚未登记此任务 | 只写一次结果，停止 | `completed=1` 与证据引用 |

所有状态都可转入 `STOPPED`：未知/多义画面、角色不符、超时、断线、环境拒绝、窗口丢失/被遮挡、缺物或未支持任务。不能把停止当成功。识别失败重试只重新观察，不能在未知状态重复输入。用户停止键须在等待和动作间持续有效。

初版验收要求可读取游戏内计数 N→N+1，并有针对本次任务的明确完成反馈。若次数不可读则停止并记为未通过，待重新校准或明确新的验收方案后再继续。仅文字消失、IDLE、奖励动画或背包物品减少不够。

## 5. 最小工作包与顺序

完整依赖和建议负责人见 [TASKS.csv](../TASKS.csv)。负责人是后续实施角色，不表示任务已派发执行。

1. **T01 环境和验收样本**：确认可运行环境，收集脱敏真图，读取当前任务。必须先满足 E0。
2. **T02 窗口与坐标**：共享唯一 HWND；同一截图/点击原点；前台、边界、尺寸检查。先做只读识别，T04 接通后才能验收一个已授权无消费点击。
3. **T03 状态识别**：登录、选角、入场、任务/交付、完成与错误页；所有动作只使用唯一候选。可与 T02 并行开发。
4. **T04 停止与记录**：总超时、有限重试、用户停止、敏感区域保护和结构化结果。在任何自动输入验收前接通。
5. **T05 登录**：按已知状态等待人工凭据输入，识别后续页面；不记录凭据，不自动接受新的协议。
6. **T06 选角与入场**：区服/人物唯一匹配，选中和入场后复核身份；保留从已登录状态续跑能力。
7. **T07 读取/接取修业**：读取已有任务与基线计数；必要时接取一次，并解析物资任务。未知分支停止。
8. **T08 核对物资**：背包查找同名物品、数量；足量继续、不足报差额。不引入采购。
9. **T09 导航和交付**：只使用真图验证过的内置任务追踪；识别目标 NPC、交付物和数量，提交一次。
10. **T10 完成与幂等**：以游戏内证据确认完成，最后计数；重复观察/重启不得把同一交付算第二次。
11. **T11 V0 独立任务验收**：在用户已登录选角后验证一次修业；保存未通过项和失败状态，不用语法检查替代游戏结果。
12. **T12 V1 完整入口验收**：接通 T05/T06 后独立验证人工凭据登录接续、自动选角/入场和一次修业。

T02/T03/T04 可分工并行；T05→T06 与 T07→T08 的识别逻辑可分别实现，但整链验收必须在同一目标客户端上串起来。后续自动采购或其他日常另建工作包，不修改“一次成功即停止”的初版验收定义。

## 6. 真实验收清单

- [ ] `inspect` 全程只读，无鼠标/键盘输入；未校准时拒绝执行。
- [ ] 用户输入凭据后能识别登录成功；验证码/协议/环境异常进入等待或停止，不能绕过。
- [ ] 指定区服和角色正确，选中态及入场身份均能复核；错误角色和多候选时不点击。
- [ ] 读取当前修业原文、数量和基线计数；已接任务不重复接取。
- [ ] 背包数量不足、OCR 低分或错误任务类型明确失败/停止，不填写成功。
- [ ] 对正确 NPC 交付正确物资，仅提交一次，没有额外购买或消费。
- [ ] 游戏计数 N→N+1，并有对应完成反馈；计数不可读时记为未通过。
- [ ] 本地完成数最后才写为 1，不自动接下一环；重复读取不会再加 1。
- [ ] 错窗、遮挡、尺寸变化、断线和用户停止均停止输入。
- [ ] 日志与证据可追溯状态转换，不含密码、验证码、账号登录信息或聊天内容；不推送到公开仓库。

结果至少含 `run_id`、`upstream_commit`、`client_version`、`calibration_id`、`status`、`last_state`、`task_fingerprint`、`completed`、`completion_before/after`、`evidence` 和 `stop_reason`。角色敏感标识只在本机使用，公开报告须脱敏。
